# GDK-00 packet contract

Status: scaffold, version `gdk.lean_context.v0`. This contract describes the compact **model-visible** representation. Full original records and authorization state remain in the host-owned session store.

## Packet fields

```json
{
  "schema": "gdk.lean_context.v0",
  "phase": "INSPECT",
  "task": "Find the function that checks candidate metadata",
  "catalog_epoch": "repo-tree@commit-id",
  "allowed_tools": ["code_search", "index_children", "read_symbol"],
  "evidence": [
    {
      "ref": "symbol://MCP/mcp02/env.py#candidate_refine",
      "source_sha256": "aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa",
      "summary": "Candidate exclusions depend on registered metadata",
      "verified": false
    }
  ]
}
```

The packet uses sorted JSON keys, stable sorted tool IDs, and evidence order `(verified descending, priority descending, ref ascending)`. `priority` is a packing-only field and is omitted from the packet. Empty evidence is allowed for initial discovery. The packet itself is not a grant of access.

`catalog_epoch` binds evidence to the repository/worktree revision. Stale entries are skipped and recorded separately in the receipt. An evidence record is considered verified only after a host-owned verifier has validated its source and claim. Any summary generated by a model is unverified until that check succeeds.

## Builder interface

```python
assemble_packet(
    *,
    task: str,
    phase: Phase,
    catalog_epoch: str,
    allowed_tool_ids: Sequence[str],
    evidence: Sequence[Evidence],
    counter: TokenCounter,
    budget: Budget = Budget(),
    external_input_tokens: int = 0,
    max_packet_tokens: int | None = None,
    require_exact: bool = True,
) -> tuple[str, PacketReceipt]
```

`external_input_tokens` must account for existing conversation, instructions, framing and tool schemas at the **same tokenizer boundary**. `require_exact=True` rejects an estimator. The builder ensures only that the returned canonical JSON packet fits its allocated share. The ultimate Rust request preparer must check the full serialized provider request again.

### Receipt fields

`tokenizer_name`, `counter_exact`, `input_capacity_units`, `external_input_units`, `packet_budget_units`, `packet_units`, `selected_refs`, `omitted_refs`, `stale_refs` and `measurement_scope`. The scope is always `canonical_packet_only` in this scaffold.

These counters intentionally carry the name *units* because the injected counter may be a synthetic test counter or an estimator. An exact model tokenizer is required before interpreting units as model tokens.

## Phase transition rules

| Current | Event | Next | Required external evidence |
| --- | --- | --- | --- |
| INSPECT | `action_selected` | ACT | Host pins action and visible catalog |
| ACT | `tool_receipt` | VERIFY | Host confirms at least one persisted receipt ID |
| VERIFY | `verified` | FINAL | Host confirms at least one trusted verifier reference |
| VERIFY | `needs_more` | INSPECT | Host records reason for retry |
| FINAL | `new_task` | INSPECT | New user request, reset task-local state |

Any other transition fails. A `tool_receipt` event from an unsuccessful or unapproved tool call must be handled as a failed observation; the host can return to inspection rather than treating it as verified evidence.

## Explicit exclusions

- This folder has no code that rewrites Goose conversations or changes a provider request.
- It never executes MCP tools or interprets source content as instructions.
- It does not implement authorization, evidence verification, persistent state, tokenizer discovery, or training.
- The synthetic unit tests do not establish real context-window compliance.

The next step is to wire a verified provider token counter and final-request preflight into an opt-in oi-kit inference adapter.
