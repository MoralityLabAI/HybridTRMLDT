# RLM x TRM/LDT Hybrid Neighborhood v1.1 Registration

This successor was frozen after the v1 calibration screen failed and before any held-out evaluation task was opened. It does not retroactively promote v1. It uses the v1 screen as explicit calibration evidence for a new rule: conductor noncompliance and bounded per-cell failures are architecture outcomes, while typed unsafe execution and provider-wide access failure remain stopping conditions.

The eleven architecture hashes, official RLM commit, provider model, prompts, four-iteration root runtime, two-iteration child runtime, task suite, trained proposal table, and three ControlTRM checkpoints are unchanged from v1. All 24 evaluation tasks remain untouched. Twelve shards cross three registered proposer seeds with four task families; each shard evaluates six tasks and all eleven architectures.

Cell errors receive zero utility and registered regret without retry or imputation. Conductor manipulation failures execute the exact LDT fallback and remain failures in the record. The aggregate wrapper allowance is three hours because the v1 calibration screen measured 693 seconds for 48 provider cells; the per-process resource caps and 30-minute shard timeout are unchanged.

The co-primary endpoints remain equal-family macro utility and unsafe executed-action rate. No scalar winner is registered. The claim boundary remains generated gym tasks, official RLM control flow, gym proxy/ControlTRM proposers, and typed LDT membranes; no official TinyRecursiveModels, Conductor-HRM, VPD, general alignment, or general model-superiority claim is licensed.
