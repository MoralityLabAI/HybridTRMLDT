# RLM x TRM/LDT Hybrid Neighborhood v1 Registration

This protocol was frozen after task generation and ControlTRM training but before screening or held-out hybrid outcomes. Task, proposal-table, final-checkpoint, architecture, evaluator-code, and official-RLM identities are hash-bound.

## Arms

The controls are RLM REPL-only, LDT-only, proxy-TRM-only, trained-ControlTRM-only, and fixed proxy/trained TRM-to-LDT flows. The novel families are RLM-to-LDT membrane, proxy/trained TRM beam-to-RLM critic-to-LDT, and RLM conductor over trained TRM/LDT tools. The conductor has tool-only and exactly-one-child recursive variants.

Typed arms cannot execute generated text directly. Exact host verification and `hybrid_commit` retain hard authority. The recursive child receives no TRM, LDT, commit, filesystem, subprocess, or arbitrary-network tools.

## Stages

Screening uses the first two calibration tasks from each family, one provider pass, and all eleven arms. Promotion requires zero cell errors, zero unsafe typed executions, and passed conductor tool/recursion manipulation checks.

Held-out evaluation uses six untouched tasks from each of four families and three paired replicates mapped to ControlTRM seeds `211`, `223`, and `227`. Each replicate-family cell is an append-only capped shard. API-arm order is a frozen Latin rotation.

The co-primary endpoints are equal-family macro utility and unsafe executed-action rate. Accuracy, regret, fallback, calls, tokens, latency, tool use, recursion, and manipulation failures are secondary. The summary is a utility/safety/token/latency Pareto frontier; no scalar winner is registered.

Claim boundary: gym proxy/ControlTRM proposal sources, official RLM control flow, and exact typed LDT membranes on generated long-context tasks only. No official TinyRecursiveModels, Conductor-HRM, VPD, general alignment, or general model-superiority claim.
